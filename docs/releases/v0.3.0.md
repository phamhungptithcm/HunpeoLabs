# Hunpeo Labs Website v0.3.0

This source release brings the Journal and Studio CMS together with the latest
website, account and contact experience. Production CMS activation remains
blocked by the operational requirements listed below; publishing this release
does not deploy the application.

## What is new

- Journal and Studio CMS with Google-only verified identity, editorial roles,
  drafts, revisions, publishing controls and private media.
- Moderated reader comments, account settings, article sharing and RSS dialogs.
- Updated English CMS labels, category navigation and shared account controls.
- Latest Contact email-brief handoff, compact footer, product pages and company
  principles retained from the committed website changes.
- Firebase Analytics loads only after explicit consent and supports revocation.
- Next.js16.3.8 and bounded dependency overrides; production audit reported no
  known advisories within its scope.

## Experience and accessibility

- Desktop/mobile navigation and responsive layouts follow the current website.
- Unknown finite service routes return real HTTP404 responses.
- Loading boundaries preserve private preview and login redirect HTTP semantics.
- Consent tests use an independent first-visit fixture; mobile tests follow the
  actual navigation menu without reverting the latest footer.
- Existing reduced-motion, no-JavaScript and privacy checks are retained.

## Delivery and operations

- Source configuration enables CMS and references the matching Firebase project,
  private bucket and runtime-only Secret Manager key. No secret value is included.
- Explicit Codex/Claude adapter selection and canonical generation checks.
- Provider preflight distinguishes infrastructure accessibility from readiness
  and rejects inline rate-limit keys or production emulator settings.
- Contact prepares an email brief; no automated contact webhook is activated.
- One Tap remains disabled. Source caches, logs and runtime data stay outside Git.

## Production limitations and rollback

Production deployment and CMS readiness are NOT_READY. Trusted ingress/IP-header
semantics and direct-backend spoof rejection must be verified before CMS login
can function safely. Live Google desktop/mobile, both initial admins, draft/media
privacy, revocation, production backup/restore and retention/monitoring acceptance
remain required. A missing trusted ingress header fails session mutations closed.

No destructive schema migration or public synthetic article publication occurs
as part of this GitHub release. The CMS persists access policy, revisions and
private records; this is not a stateless foundation release. Preserve database,
Auth identities, media and the one-time access-policy marker. Disable the CMS
feature flag to pause traffic and fix forward from patched source. Do not reset
editorial policy, restore revoked grants or delete data for rollback.
