# Hunpeo Labs Website v3.1.0

Journal and Studio improvements, production Google One Tap configuration, and atomic CMS rate limiting.

## Changes
- Enable Google One Tap with the matching Firebase Google Web client ID.
- Consume per-user and shared action budgets atomically; fail closed on provider failures.
- Improve editor media, Mermaid diagrams, taxonomy fields, preview/history controls and dialogs.
- Add scheduled publication source, reader view/share endpoints and UI, and login error labels.
- Configure daily Firestore backup retention of 14 days and production health monitoring through approved operations.

## Validation and limits
Release CI validates frozen dependencies, lint, types, unit tests, production build, desktop/mobile and cross-browser smoke, and Lighthouse. Counts and success are scoped to the actual release workflow.
Google GIS initialization was observed on production; real Google account sign-in, private media/revocation and a complete backup restore remain unverified. The earlier generic manual login error has not been certified resolved. Browser/account policies may suppress One Tap.
View/share recording also remains fail-closed until trusted ingress and receipt TTL prerequisites are verified; counts may remain hidden on production. Existing session/comment/report UID + shared atomic limiting is preserved.
Scheduled publishing requires separate production scheduler/secret provisioning; this release does not activate a cron job. Destructive retention cleanup is not activated. Firestore backup does not cover Firebase Auth or Storage.

## Deployment and rollback
Deploy the tagged main source to the existing Firebase App Hosting backend hunpeolabs in hunpeolabs-prod. Preserve editorial policy, identities, private media and database contents. Roll back to the previous ready revision if necessary; never reset CMS data to roll back source.
